# RLCD Clock 开机配置与 TF 文件管理

项目内部名称为 rlcd_clock，设备显示名由 device.name 决定，默认 HUANGLE。

## 更新

双击 `Device_Update.command` 烧录随项目提供的固件。脚本不再在烧录后发送默认城市或 Wi-Fi 覆盖 TF 卡设置。修改电脑上的 `device.config.json` 后需要重新编译，才会进入默认固件；修改 TF 配置只需重启设备。

默认配置会嵌入固件（包含其中的 Wi-Fi 信息），分享固件前请使用不包含个人凭据的默认配置重新编译。`device.config.local.json` 仅供电脑更新脚本指定端口或显式串口配网使用，不会自动替换编译默认配置。

## TF 开机配置

使用 FAT32 TF 卡，关机插卡。将 `examples/boot/setting.json` 复制到卡根目录的 `/boot/setting.json`，替换 Wi-Fi 名称与密码。`port` 是电脑串口设置，设备忽略它。

- 开机先加载编译默认配置，再应用合法的 TF 配置；缺失字段沿用默认值。
- 配置最大 8 KiB，UTF-8（支持 BOM）。字段类型或范围错误时整份 TF 配置不生效，设备仍能进入主页。
- 城市名变更必须同时提供经纬度，使用 WGS84 十进制度数。
- `device.name` 最长 48 个 UTF-8 字节；主菜单显示全名，页脚仅显示前四个字符（默认 HUANGLE 保留原样）。适合网络主机名的英文数字连字符名称同时用于 Wi-Fi hostname，其余名称使用 rlcd-clock 作为网络主机名。
- 无 TF 配置时，城市沿用内部存储中的用户选择；首次使用采用编译默认值。无有效 TF 配置不会清空已有内部设置。
- 设置页选城市：有卡时保存到 TF 配置并保存内部设置；无卡时保存内部设置。若本次开机曾使用 TF 配置，运行中拔卡后禁止修改城市，以免重启恢复旧配置。配置写入失败会提示失败，不显示保存成功。
- 保存使用临时文件与 `.bak` 备份；启动时主文件丢失而备份存在，会尝试恢复。FAT 卡断电写入仍需实机验证，不保证任意断电时刻的文件系统完整性。
- 不会自动格式化 TF 卡。未插卡、挂载失败或运行中移除卡均提供错误提示；本版重新插卡后请重启。

## 文件管理

主页选择“文件管理”进入卡目录，文件保持原始目录顺序。BOOT 短按选择，KEY 短按打开，KEY 长按返回上级；根目录长按返回主页。每页五项，下方“上一页 / 下一页”翻页。

文本阅读：BOOT 短按下一页，KEY 短按上一页，KEY 长按返回目录。自动换行，支持 UTF-8 中文、英文、BOM 和 CRLF/LF。暂不支持 GBK、UTF-16、图片、PDF、压缩包或二进制内容；字体库未收录的字符不保证显示。

支持 txt、json、log、xml、csv、md、ini、conf、cfg、yaml、yml、toml、html、css、js、py、c、cpp、h、sh、sql、properties，扩展名不区分大小写。所有格式仅按纯文本显示，不执行脚本、不解析 HTML。最大单文件 16 MiB，最多浏览 8192 页；按页读取，页索引最多约 32 KiB。

文件浏览只读，不提供编辑、删除或创建操作（设置功能写 `/boot/setting.json` 除外）。

## 城市选择

34 个省级分组、380 个天气地点，包含大陆地级行政区、四个直辖市、省直辖地点，以及港澳和台湾主要市级地点。原长三角 41 城市的顺序与坐标保留。主页长城市名仅显示前四字符，设置页保存完整名称。

数据与出处见 `design/cities-national.json`。DataV 城市中心坐标近似转换到 WGS84，供城市级天气定位使用，不作测绘用途。台湾地点取 Open-Meteo / GeoNames；新星、白杨补充坐标有单独出处。运行 `python3 tools/generate_cities.py` 可重建城市头文件。

## 实机验收

1. 不插卡启动，检查原时钟、天气、按键和营地动画。
2. 使用有效 TF 配置启动，检查设备名、Wi-Fi、城市；断电重启后再次确认。
3. 从设置切换城市，检查卡上的 JSON 与重启后的城市一致，Wi-Fi 和设备名不丢失。
4. 试验缺失配置、格式错误配置、空目录、多页目录、中文文件名、UTF-8/GBK/二进制文件。
5. 确认文本前后翻页、目录返回、移除卡后的提示正常。

自动化测试与编译不能代替这些 TF 卡和开发板实测。
